## Static design

There are two static designs, `fir` and `iir`. They differ only in the filter cell. The static design reads the IMU, filters the samples and writes them into a BRAM that the PS reads. The block diagram, the BRAM layout, the EMIO bits, SW1 and the LEDs are in `../docs/imu_system.md`.

## DFX design

One reconfigurable partition (RP) holds the CNN or the SNN. The PS swaps them with a partial bitstream over PCAP. No PL logic takes part in the reconfiguration.

```
            M_AXI_GP0                          s_axi_control
  PS7  ───────────────► sc_ctrl ──► ┌─────────┐ ───────────► ┌──────────────┐
                                    │   DFX   │              │  rp          │
            S_AXI_HP0               │decoupler│  m_axi_gmem  │  rm_cnn  or  │
       ◄─────────────── sc_mem  ◄── └─────────┘ ◄─────────── │  rm_snn      │
                                         ▲                   └──────────────┘
            EMIO GPIO bit 0              │ decouple                 ▲ ap_rst_n
       ──────────────────────────────────┴──► rst_rp (aux reset) ───┘
```

The second master port of `sc_ctrl` goes to `imu_bram_ctrl`, the AXI BRAM controller of the IMU capture BRAM.

| Part | Function |
|---|---|
| `ps7` | PYNQ-Z2 board preset. FCLK0 at 100 MHz clocks all of the PL. GP0 master, HP0 slave, 3 EMIO GPIO bits (decouple, capture clear, SW1). UART0 on MIO |
| `sc_ctrl`, `sc_mem` | SmartConnects: PS to the accelerator registers and the IMU BRAM, accelerator to DDR |
| `decoupler` | DFX Decoupler with two interfaces. It isolates the RP during the reconfiguration |
| `rst_static`, `rst_rp` | Reset of the static AXI logic, and a separate reset of the RP that is also set while the RP is decoupled |
| `rp` | Block design container with DFX. Its modules are the block designs `rm_cnn` and `rm_snn`, each with one HLS IP named `accel` |

Contract with the PS (`../ps/ps_dfx.c`, `../ps/ps_accel.c`):

- EMIO GPIO bit 0 (PS GPIO pin 54) high: the RP is decoupled and in reset. Low: coupled, reset released 56 clock cycles later (assignment 2 simulation).
- Accelerator registers at `0x4000_0000`, 64K, for the module that is loaded. IMU capture BRAM at `0x4200_0000`, 16K.
- The AXI master of the accelerator sees all of DDR through HP0.
- No interrupt. The PS polls `ap_done`.

RP boundary, the same for each module: `ap_clk`, `ap_rst_n`, `s_axi_control` (AXI4-Lite slave), `m_axi_gmem` (AXI4 master). `dfx_project.tcl` finds the interfaces of the IP by type, so the bundle names in the HLS source can be different.

Floorplan: the RP has the two lower clock region rows of the device. The static logic is in the upper row, next to the PS. See `constraints/dfx_pblock.xdc`. To do: move the RP to clock regions X1Y0..X1Y2 at the next rebuild.

## Build

The commands are in `../build_guide.md`, step 4. Notes:

- `dfx_project.tcl` deletes `vivado/dfx_<filter>/` and builds it again. Run it again after each change of an IP, a filter or the RTL. Read the lines that start with `DFX:` in the output.
- The script takes the modules from `ip/`. To use other IPs, set `modules` before you source the script, for example `set modules {rm_cnn imu_cnn rm_snn imu_snn}`.
- Check in the **Address Editor**: the accelerator is at `0x4000_0000`, `imu_bram_ctrl` at `0x4200_0000`.
- **Tools > Dynamic Function eXchange Wizard** shows one configuration per module: `impl_1` and one child run. If the script could not make them, make them here: **automatically create configurations**, then **automatically create configuration runs** (Standard DFX).
- The full bitstream and the two partial bitstreams belong together. A partial bitstream only works with the static design that it was implemented with. After each implementation run, export all three files again and rebuild the PS application.

## Status (26 Nov 2026)

Both designs are built and tested on the board (`../docs/imu_system.md`, "Verification on the board"). Timing is met: FIR WNS +1.14 ns / +0.42 ns, IIR +1.28 ns / +0.88 ns (CNN / SNN configuration).

Points to check when the IMU models replace the placeholders:

- **RP boundary.** Vivado requires the same ports on all modules. Make the AXI master read-only in both models (`const` pointer).
- **Clock.** The static design clocks the RP at 100 MHz. The HLS target must be 10 ns or less.
- **Size.** Check the RP utilization of each module in both implementation runs. If a module does not fit, change the pblock (see the comments in the XDC).
